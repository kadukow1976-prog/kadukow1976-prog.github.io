# Android Control Hub — Windows 0.3.2 Beta

## Исправлено по результату OnePlus 15 / OxygenOS 16

При выполнении `pm clear` для Ozon система вернула код **255** и исключение **SecurityException** — `android.permission.CLEAR_APP_USER_DATA` не предоставлено ADB-оболочке. Это отказ Android, а не ошибка подключения.

- При `CLEAR_APP_USER_DATA` программа сообщает: **«Android запретил очистку данных; данные не очищены»**, сохраняя системную ошибку в журнале.
- При ошибке одного выбранного приложения она безопасно открывает штатную карточку этого приложения на телефоне для ручной очистки.
- Программа **не** заменяет очистку данных удалением приложения и не обходит защиту.
- Успех «Удалить для профиля» означает выполнение `pm uninstall --user <текущий профиль>`, но не доказывает полное удаление данных и резервных копий.
- Проверяйте полную очистку только на приложении без важных данных.



## Исправлено по скриншоту OnePlus 15 / Android 16

**Причина сбоя — 60-секундный тайм-аут команды `adb shell pm clear --cache-only`.** Это не доказательство отказа в разрешении и не подтверждение, что кэш не очищен. На стороне устройства операция могла ещё выполняться; повторять её автоматически нельзя.

- При тайм-ауте программа показывает «РЕЗУЛЬТАТ НЕИЗВЕСТЕН», сохраняет исходную ошибку в журнале.
- Если очистка только кэша одного приложения завершилась с ошибкой, Android Control Hub автоматически открывает **сведения об этом приложении на самом телефоне**. Дальше владелец может выбрать «Память/Хранилище → Очистить кэш».
- Есть отдельная кнопка **«Настройки»** в списке программ — она открывает сведения выбранного пакета на телефоне через защищённый ADB Intent.
- Программа **не запускает** `pm clear` без `--cache-only` вместо очистки кэша: это безвозвратно удалило бы локальные данные приложения.
- Все действия ведутся через авторизованное USB/ADB; сторонние файлы не считываются. Прямое открытие системных настроек не изменяет данные.
- CI использует тесты с имитированным ADB. Нужно проверить на OnePlus, что система открывает правильную карточку и позволяет ручную очистку.


Тестовая программа для Windows 10/11: ADB-диагностика и обслуживание телефона владельца или устройства, предоставленного владельцем для диагностики.

## Что исправлено по итогам теста на OnePlus

1. **Русские пояснения.** Диагностика устройства больше не разворачивает полный технический вывод в длинные непонятные блоки: заряд, температура АКБ, напряжение, версия системы, ОЗУ и память отображаются в компактной сводке. Подробные исходные данные доступны в экспортируемом JSON.
2. **Сведения о приложениях.** Типовые разрешения Android описываются по-русски. Наличие разрешения на наложение окон или автозапуск не является доказательством рекламы или вируса.
3. **Ошибка очистки кэша.** Если Android отклонил `pm clear --cache-only` или не поддерживает его, программа показывает конкретную ошибку и рекомендует штатное меню «Настройки → Приложения → Память → Очистить кэш». Команда полной очистки вместо кэша **никогда не запускается**.
4. **Меньше лишних подтверждений.** Кэш, остановка приложения, включение и чтение разрешений выполняются без дополнительного диалога. Для отключения, удаления и полного стирания данных требуется **одно явное подтверждение на выбранную группу** — без повторного ввода слов.
5. **Отдельные действия.** В списке пакетов появились заметные кнопки **«Удалить выбранные приложения»** и **«ПОЛНАЯ очистка данных»**. Обе операции реальны и выполняются через авторизованный ADB. Удаление `pm uninstall --user <текущий профиль>` удаляет пользовательское приложение для текущего профиля (это не сброс телефона); очистка `pm clear --user` удаляет его локальные данные. Перед этими действиями сохраните резервную копию важных файлов и данных самих приложений.
6. **Компактнее.** Уменьшены высота интерфейса, отступы, высота строк и область вкладок.

## Доступ к инструментам

На первом запуске программа ищет полный комплект `adb.exe`, `fastboot.exe` и двух DLL в собственном каталоге, Android SDK и PATH. Если комплект отсутствует, загружает официальный пакет Google Platform Tools в `%LOCALAPPDATA%\AndroidControlHub\platform-tools`. При сетевой ошибке доступна повторная загрузка и ручной выбор папки.

На телефоне включите **отладку по USB** и подтвердите запрос ключа RSA. Если статус `unauthorized`, повторите подтверждение на телефоне. Shizuku на компьютере не требуется.

## Что поддерживается

USB/ADB диагностика, экранные параметры ОС и питания, пользовательские пакеты, признаки автозапуска и overlay, установка APK/split APK, экспорт APK, копирование общих каталогов, Fastboot (чтение свойств), журнал и выгрузка JSON.

Операции не дают root и не читают защищённые базы, пароли, криптографические ключи и приватные файлы сторонних приложений. Подтверждение необратимых действий остаётся обязательным.

## Тестирование и выпуск

GitHub Actions Windows build: исходный архив 0.1 → патч зависимостей 0.2 → патч компактного интерфейса 0.3 → исправления 0.3.1 и 0.3.2 → Python unittest → PyInstaller EXE → ZIP/release.

Тесты используют имитированный ADB. Перед применением к клиентским телефонам проверить на реальном OnePlus Android 16: очистку только кэша, выдачу понятной ошибки при отказе, запреты системных пакетов, пакетное удаление и полную очистку **только тестового приложения без важных данных**.

Если будущий выпуск содержит новые опасные операции, следует предварительно проверить его на резервном тестовом устройстве. Не подписан издательским сертификатом; Windows может показать предупреждение SmartScreen.
