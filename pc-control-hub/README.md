# Android Control Hub — Windows 0.3.9 Beta

## Новая безопасная диагностика ADB / Fastboot / fastbootd

Во вкладке **«Полномочия»** появилась кнопка **«Диагностика ADB/Fastboot (только чтение)»**. Работает даже без выбранного Android-устройства. Показывает версии локальных ADB и Fastboot, пути к файлам, подключённые устройства ADB и статусы `device` / `unauthorized` / `offline` / `recovery` / `sideload`.

Для устройств, найденных через `fastboot devices`, по конкретному серийному номеру вызываются только `fastboot -s SERIAL getvar is-userspace` и `getvar current-slot`. Значение `yes` означает fastbootd, `no` — Fastboot загрузчика. Если производитель не поддерживает переменную, показывается «тип Fastboot не определён» без предположений. Никаких команд прошивки, стирания, разблокировки или перезагрузки.

Проверяется локальная версия Platform-Tools; если она старее **37.0.1** (официальный выпуск Google от июля 2026), показывается рекомендация обновления, но программа не заменяет работающие инструменты автоматически. При отсутствии ADB/Fastboot используйте существующую функцию восстановления официального пакета.

Результат проверен автоматическими тестами с поддельными ответами ADB/Fastboot. Проверка на реальных устройствах и отдельных OEM-загрузчиках ещё требуется.



## Исправлено: агент «установлен» в Windows, но отсутствует на телефоне

В предыдущих версиях версия агента считывалась из общего каталога Package Manager. Android может помнить `versionCode 9`, даже когда программа не установлена для активного пользователя.

Новая версия проверяет **активный профиль** через `am get-current-user` и `pm list packages --user <профиль>` без флага `-u`. Только наличие пакета в этом списке доказывает его установку для выбранного профиля. `-u` служит лишь для поиска сохранённого в системе APK, а не для вывода ложного «установлено».

Состояния: «установлен», «отключён», «удалён для профиля, но APK сохранён», «не установлен», «не удалось проверить». При наличии сохранённого пакета кнопка «Скачать / обновить агент» предложит **восстановить через `cmd package install-existing --user`**. Это требует явного согласия и не очищает данные. Если APK в системе нет — предлагается обычная загрузка проверенного релиза с GitHub. Если агент отключён — отдельное согласие на включение.

Кнопка «Открыть агент на телефоне» запускает только известную активность `ru.kadukov.androidcontrolhub/.WorkshopActivity` через ADB, без получения root и без изменения разрешений. В исходном AndroidManifest она объявлена как MAIN/LAUNCHER. Если приложение установлено, но значок скрыт оболочкой, это поможет отличить проблему запуска от отсутствия APK.

**Не удаляйте мобильное приложение и не очищайте его данные для диагностики.** Команды восстановления, включения и запуска выполняются только после выбора устройства и проверки активного пользователя.

Проверки CI с эмулятором ADB; реальное выполнение на OnePlus 15 ещё необходимо подтвердить.



## Исправлено несоответствие статуса агента на OnePlus 15

На скриншоте после проверки Windows 0.3.6 виден правильный результат «Android Control Hub Agent versionCode 9 уже установлен», но в фоновом окне «Полномочия» по-прежнему показывается «Сервисный агент — Не найден».

Это расхождение двух разных способов поиска: старый блок «Полномочия» опирался только на `pm path`, а обновление уже использовало дополнительные `pm list packages --show-versioncode` и `cmd package list packages --show-versioncode`. На некоторых прошивках OxygenOS `pm path` может завершаться кодом 1, хотя пакет установлен.

- **Центр полномочий теперь использует тот же алгоритм, что и проверка обновлений.**
- Отображает «Установлен · versionCode 9» при подтверждённой версии, «Установлен · версия не определена» при обнаруженном пакете или «Не удалось проверить» при отказе ADB. Ошибка доступа больше не отображается как отсутствие агента.
- После «Скачать / обновить агент» статус в основной панели автоматически обновляется.
- При текущей версии 9 переустановка агента не нужна. Очистка данных, сброс телефона или отключение системных служб не запускаются.
- Shizuku остаётся отдельной зависимостью и должен быть установлен и запущен на самом телефоне, чтобы расширенные команды стали доступны.

Тестировано автоматическими проверками с симуляцией ответа OxygenOS 16, где `pm path` отвергается, но `pm list packages` возвращает версию 9. Реальные ADB-запросы и обновление интерфейса ещё требуют проверки на OnePlus.



## Исправлено: «Ошибка adb (код 1)» при проверке агента

На OnePlus 15 с Android 16 кнопка «Скачать / обновить агент» могла завершаться ошибкой из-за команды `dumpsys package`, используемой для чтения установленного `versionCode`.

Новый алгоритм: определить пакет через `pm path`, затем запросить версию через `dumpsys package`. Если `dumpsys` завершилась с кодом 1 или не содержит версию нужного пакета, запросить `pm list packages --show-versioncode` и `cmd package list packages --show-versioncode`. Команды только читают информацию и не меняют устройство.

- При подтверждённой уже установленной версии `versionCode 9` агент повторно не устанавливается.
- При неизвестной версии установка блокируется, показывается список ошибочных ADB-запросов; понижать версию или удалять данные не предлагается.
- Проверка всегда относится к конкретному пакету `ru.kadukov.androidcontrolhub`, исключено чтение номера версии другого приложения.
- Если соединение не позволяет получить ни существование пакета, ни его версию, программа сообщает диагностическую ошибку и не начинает скачивание/установку.
- При наличии настоящего устаревшего агента сохраняются проверка SHA-256 файла с официального GitHub и отдельное согласие перед установкой.

**Тесты:** имитация отказа `dumpsys`, отказа `pm path`, повторных ошибок ADB, неверного пакета и защиты от незапрошенных установок. Реальная проверка на OnePlus 15 после сборки обязательна.



## Исправлена установка агента на OnePlus 15

По скриншоту причина — `INSTALL_FAILED_VERSION_DOWNGRADE`: выбран `android-hub-beta-0.2.apk` с versionCode 2, а на телефоне установлена версия с versionCode 9.

- В центре полномочий добавлена кнопка **«Скачать / обновить агент»**. Она читает проверенный манифест последнего опубликованного релиза из GitHub (при недоступности сети использует встроенный эталон версии 0.8.1), затем определяет установленный `versionCode` через ADB.
- Если агент уже установлен и его код версии равен **9** или выше, повторная установка или понижение не запускаются.
- Если агент отсутствует либо старее, только после согласия пользователя Windows скачивает официальный APK по HTTPS, проверяет **размер и SHA-256**, затем запускает обычную установку через ADB без флага `-d` и без удаления существующего агента.
- При неразборчивом ответе Android о версии установка не выполняется автоматически.
- Кнопка ручного выбора **«Установить проверенный APK»** принимает только APK с контрольной суммой официального актуального релиза. Старый `android-hub-beta-0.2.apk` отклоняется с русским объяснением. Другие приложения устанавливаются из вкладки **«Установка / Fastboot»**.
- Файлы скачиваются во временный каталог `%LOCALAPPDATA%\AndroidControlHub\agents`; при повреждении архив очищается, уже установленная рабочая версия остаётся на телефоне.
- На данный момент официальный агент: **Android Control Hub 0.8.1-beta**, versionCode 9. Проверенный релиз: https://github.com/kadukow1976-prog/kadukow1976-prog.github.io/releases/tag/android-hub-beta-0.8.1
- Установка APK не выдаёт Device Owner, root или system UID и не включает Shizuku. Shizuku на скриншоте не установлен.

**Проверено:** автоматические тесты версии, неверного хеша, офлайн-манифеста, отсутствия агента и защиты от downgrade. Работа на реальном OnePlus должна быть проверена после сборки Windows EXE.



## Новое: Центр полномочий Android

Новая вкладка **«Полномочия»** показывает фактическую, а не желаемую, степень доступа:
- **ADB shell:** подтверждает UID активной ADB-оболочки `id -u` (обычно 2000).
- **Android Control Hub Agent:** проверяет наличие APK `ru.kadukov.androidcontrolhub` и позволяет вручную выбрать доверенный агент APK для установки через авторизованный ADB, с отдельным подтверждением владельца.
- **Shizuku:** проверяет наличие приложения; это не доказывает запуск службы или выдачу разрешения нашему агенту. Для расширенных функций Shizuku необходима настройка владельцем телефона.
- **Device Admin:** обычный администратор телефона не имеет полного доступа к данным сторонних программ, в отличие от корпоративной модели управления.
- **Profile Owner:** режим управления отдельным рабочим профилем после соответствующего корпоративного развёртывания.
- **Device Owner:** отдельный DPC и поддерживаемое корпоративное развёртывание. Для производственного устройства обычно требуется подготовка на этапе первичной настройки или сброса. Не активируется кнопкой в текущем инструменте.
- **Root, system UID, OEM privileged signature:** не могут быть выданы кнопкой, паролем экрана, установкой APK или Device Admin. Их наличие не предполагается.
- **SELinux / тип сборки:** проверяются информационно и не изменяются.

Рабочие кнопки: **«Проверить уровни», «Установить APK агента», «Настройки агента»**, ссылки на официальные руководства Shizuku и Android Enterprise. Установка выполняется только после выбора файла и явного согласия. Проверка разрешений не активирует Device Owner, root, Shizuku и не выполняет `pm grant`, `appops set`, очистку данных или сброс.

**Ограничения:** Агент 0.8.1 уже умеет работать с Shizuku UserService при предварительной настройке Shizuku на телефоне, но работа на OxygenOS 16 в этом режиме требует проверки. Установить агент — не значит получить административные или системные права. Центр доступа в Windows 0.3.4 не является автоматическим DPC-провижинингом. Действия с приложениями остаются в отдельном менеджере и сохраняют подтверждение необратимых операций.

Ссылки: https://developer.android.com/work/dpc/device-management.html · https://developer.android.com/work/dpc/dedicated-devices · https://shizuku.rikka.app/guide/setup/



## APP Manager — пакетная обработка как в SamFw Tool

Выберите приложения **галочками** в первом столбце. Кнопка «✓ Отметить видимые» выделяет только результаты текущего поиска; «Снять отметки» очищает выбор. Отметки сохраняются при смене фильтра. В режиме без галочек по-прежнему работают Ctrl/Shift.

Действия по группе: **очистка кэша**, **очистка всех данных**, **остановка**, **отключение**, **включение**, **удаление для текущего профиля**. Для удаления, полной очистки и отключения обязательно предварительное подтверждение с перечнем пакетов. Ключевые системные приложения не разрешается изменять.

Результат для каждого пакета: успех, ошибка либо **пропущено без запуска**. Если Android 16 отказал в праве CLEAR_APP_USER_DATA, пакетная очистка прекращается после первой такой ошибки (не запускается бесконечно для всех программ). Приложения, которые остались неочищенными, можно выбрать в отдельном окне и открыть их системные настройки на телефоне для ручной очистки. Аналогично, если очистка только кэша завершилась тайм-аутом, пакетные команды останавливаются, а результат не считается успешным.

**Ограничение OnePlus 15:** оболочке ADB не выдано CLEAR_APP_USER_DATA. Само по себе повторение операции, смена кнопки или поддержка SamFw Tool не снимут этот запрет. Очистка кэша не подменяется полной очисткой, а полная очистка — удалением приложения.

Сначала проверяйте на одном приложении без важных данных. На физическом OnePlus эта версия пока не испытана.



## Исправлено по результату OnePlus 15 / OxygenOS 16

При выполнении `pm clear` для Ozon система вернула код **255** и исключение **SecurityException** — `android.permission.CLEAR_APP_USER_DATA` не предоставлено ADB-оболочке. Это отказ Android, а не ошибка подключения.

- При `CLEAR_APP_USER_DATA` программа сообщает: **«Android запретил очистку данных; данные не очищены»**, сохраняя системную ошибку в журнале.
- При ошибке одного выбранного приложения она безопасно открывает штатную карточку этого приложения на телефоне для ручной очистки.
- Программа **не** заменяет очистку данных удалением приложения и не обходит защиту.
- Успех «Удалить для профиля» означает выполнение `pm uninstall --user <текущий профиль>`, но не доказывает полное удаление данных и резервных копий.
- Проверяйте полную очистку только на приложении без важных данных.



## Исправлено по скриншоту OnePlus 15 / Android 16

**Причина сбоя — 60-секундный тайм-аут команды `adb shell pm clear --cache-only`.** Это не доказательство отказа в разрешении и не подтверждение, что кэш не очищен. На стороне устройства операция могла ещё выполняться; повторять её автоматически нельзя.

- При тайм-ауте программа показывает «РЕЗУЛЬТАТ НЕИЗВЕСТЕН», сохраняет исходную ошибку в журнале.
- Если очистка только кэша одного приложения завершилась с ошибкой, Android Control Hub автоматически открывает **сведения об этом приложении на самом телефоне**. Дальше владелец может выбрать «Память/Хранилище → Очистить кэш».
- Есть отдельная кнопка **«Настройки»** в списке программ — она открывает сведения выбранного пакета на телефоне через защищённый ADB Intent.
- Программа **не запускает** `pm clear` без `--cache-only` вместо очистки кэша: это безвозвратно удалило бы локальные данные приложения.
- Все действия ведутся через авторизованное USB/ADB; сторонние файлы не считываются. Прямое открытие системных настроек не изменяет данные.
- CI использует тесты с имитированным ADB. Нужно проверить на OnePlus, что система открывает правильную карточку и позволяет ручную очистку.


Тестовая программа для Windows 10/11: ADB-диагностика и обслуживание телефона владельца или устройства, предоставленного владельцем для диагностики.

## Что исправлено по итогам теста на OnePlus

1. **Русские пояснения.** Диагностика устройства больше не разворачивает полный технический вывод в длинные непонятные блоки: заряд, температура АКБ, напряжение, версия системы, ОЗУ и память отображаются в компактной сводке. Подробные исходные данные доступны в экспортируемом JSON.
2. **Сведения о приложениях.** Типовые разрешения Android описываются по-русски. Наличие разрешения на наложение окон или автозапуск не является доказательством рекламы или вируса.
3. **Ошибка очистки кэша.** Если Android отклонил `pm clear --cache-only` или не поддерживает его, программа показывает конкретную ошибку и рекомендует штатное меню «Настройки → Приложения → Память → Очистить кэш». Команда полной очистки вместо кэша **никогда не запускается**.
4. **Меньше лишних подтверждений.** Кэш, остановка приложения, включение и чтение разрешений выполняются без дополнительного диалога. Для отключения, удаления и полного стирания данных требуется **одно явное подтверждение на выбранную группу** — без повторного ввода слов.
5. **Отдельные действия.** В списке пакетов появились заметные кнопки **«Удалить выбранные приложения»** и **«ПОЛНАЯ очистка данных»**. Обе операции реальны и выполняются через авторизованный ADB. Удаление `pm uninstall --user <текущий профиль>` удаляет пользовательское приложение для текущего профиля (это не сброс телефона); очистка `pm clear --user` удаляет его локальные данные. Перед этими действиями сохраните резервную копию важных файлов и данных самих приложений.
6. **Компактнее.** Уменьшены высота интерфейса, отступы, высота строк и область вкладок.

## Доступ к инструментам

На первом запуске программа ищет полный комплект `adb.exe`, `fastboot.exe` и двух DLL в собственном каталоге, Android SDK и PATH. Если комплект отсутствует, загружает официальный пакет Google Platform Tools в `%LOCALAPPDATA%\AndroidControlHub\platform-tools`. При сетевой ошибке доступна повторная загрузка и ручной выбор папки.

На телефоне включите **отладку по USB** и подтвердите запрос ключа RSA. Если статус `unauthorized`, повторите подтверждение на телефоне. Shizuku на компьютере не требуется.

## Что поддерживается

USB/ADB диагностика, экранные параметры ОС и питания, пользовательские пакеты, признаки автозапуска и overlay, установка APK/split APK, экспорт APK, копирование общих каталогов, Fastboot (чтение свойств), журнал и выгрузка JSON.

Операции не дают root и не читают защищённые базы, пароли, криптографические ключи и приватные файлы сторонних приложений. Подтверждение необратимых действий остаётся обязательным.

## Тестирование и выпуск

GitHub Actions Windows build: исходный архив 0.1 → патч зависимостей 0.2 → патч компактного интерфейса 0.3 → исправления 0.3.1 и 0.3.2 → Python unittest → PyInstaller EXE → ZIP/release.

Тесты используют имитированный ADB. Перед применением к клиентским телефонам проверить на реальном OnePlus Android 16: очистку только кэша, выдачу понятной ошибки при отказе, запреты системных пакетов, пакетное удаление и полную очистку **только тестового приложения без важных данных**.

Если будущий выпуск содержит новые опасные операции, следует предварительно проверить его на резервном тестовом устройстве. Не подписан издательским сертификатом; Windows может показать предупреждение SmartScreen.
