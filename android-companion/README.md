# Android Control Hub — сервисный Android-клиент (бета 0.1)

Нативное приложение для **локального** обслуживания Android, в дополнение к [веб-панели](https://kadukow1976-prog.github.io/android-control-hub/).

## Возможности
- Диагностика: модель, версия Android, батарея, температура, напряжение, раздел /data, свободная и полная ОЗУ, тип сети.
- Сохранение JSON-отчёта через системное окно выбора файла; отправка отчёта только вручную через Android Sharesheet.
- Экспорт **всех контактов с телефонами или email** в VCF — после отдельного согласия и разрешения READ_CONTACTS.
- Выбор нескольких файлов через Storage Access Framework и передача через Android Sharesheet.
- Список приложений с ярлыками запуска (не полный список всех системных пакетов) и переход в системные настройки выбранного приложения.
- Статистика использования приложений за последние ~24 ч, только при отдельном разрешении Usage Access.
- Переход в штатные настройки Android.

## Приватность и ограничения
- **Нет сервера, удалённого управления, скрытого сбора данных и автоматической отправки контактов**. Приложение работает локально.
- Нет SMS, звонков, доступа к паролям, root, скрытых Accessibility-служб или Device Administrator.
- Большинство действий не требуют разрешений. READ_CONTACTS запрашивается только при нажатии на экспорт. Usage Access пользователь выдаёт вручную, если ему нужна статистика.
- Google и производители Android могут ограничивать часть API в зависимости от прошивки.
- Перед экспортом контактов убедитесь, что у вас есть право обрабатывать их персональные данные.
- Это **исходный проект**, а не готовый публично подписанный APK. Для клиентов используйте тестовую сборку только после испытаний, для массового распространения — отдельную подписанную release-сборку.

## Сборка в Android Studio
1. Android Studio → Open → папка android-companion.
2. Установите SDK Platform 35 и JDK 17.
3. Синхронизируйте Gradle (AGP 8.7.3, Gradle 8.9).
4. Build → Build APK(s) → app/build/outputs/apk/debug/app-debug.apk.
5. Установите на свой тестовый Android. Пройдите сценарии ниже и сохраните лог при ошибке.

## Тест-план
- Запуск приложения на Android 10, 13, 15 или 16.
- Сканирование: сравнить батарею, свободное место раздела /data, RAM с системными настройками (с учётом разных методов учёта).
- JSON: создать документ, открыть и проверить корректность.
- Контакты: отказать в разрешении → стабильная работа; разрешить → экспорт VCF; открыть его в приложении «Контакты».
- Файлы: выбор одного и нескольких → поделиться через системный chooser.
- Приложения: список показывает приложения с ярлыком; по нажатию открываются их настройки.
- Usage Access: доступ не выдан → явное объяснение; выдан → статистика; отозван → нет чтения.
- Тесты без интернета и после поворота экрана.
- Проверить, что нет фоновой отправки данных и приложение можно удалить обычным способом.

## CI сборка
Workflow .github/workflows/android-companion.yml запускается при изменениях исходников Android-клиента, компилирует debug APK и выкладывает его как artifact GitHub Actions. Артефакт предназначен для тестирования, не для продажи и не для распространения среди клиентов. Каждый CI запуск может подписываться отдельным debug-ключом.
