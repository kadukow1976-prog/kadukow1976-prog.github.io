## Версия 0.6 — контроль приложений и личных файлов

**Вход:** «Обзор → Автоскан», «Приложения → Автоматический аудит» либо «Данные → Контроль приложений».

**Сканирование** запускается при открытии нового экрана на устройстве, в отдельном потоке без замедления интерфейса. Для полной инвентаризации локальной сервисной утилиты объявлено `QUERY_ALL_PACKAGES`: это не runtime-разрешение и отдельной кнопки «Выдать» не имеет. Для публикации в Google Play необходимо обоснование и декларация Google Play Policy.

**Категории сканирования:** предполагаемые наложения окон (заявленный `SYSTEM_ALERT_WINDOW`, факт выдачи другой программе не гарантирован), право получения BOOT_COMPLETED, объявленные JobService и точные таймеры (не подтверждают реальное выполнение), игры по категории приложения, зарегистрированные события экрана/foreground-служб, если пользователь отдельно выдал Usage Access. Это сигналы для диагностики, НЕ доказательство вредоносности и не готовый антивирус.

**Выбор программ:** галочки, поиск, фильтры. Для каждого выбранного приложения — открытие системных настроек, переход к кэшу и данным, штатному отключению, экрану разрешения наложения, обновлению Google Play или системному удалению. Кнопки «Удалить выбранные», «Отключить выбранные», «Очистить кэш выбранных», «Очистить данные выбранных» проводят владельца через каждое приложение с отдельным подтверждением. Никакой скрытой массовой очистки или `pm clear` без root/system privileges.

**Личные файлы:** отдельный экран с выбором через Android Storage Access Framework (SAF) и созданием локальной копии в выбранной папке. Удаление выбранных личных документов требует двух подтверждений и возможно лишь там, где поставщик документов разрешает удаление. Приложение НЕ получает доступ к защищённым данным установленных программ (`/data/data/<package>`) и не обещает резервировать игровые сохранения, переписки, пароли или базы данных сторонних приложений.

**Скрытые процессы/скрипты/отложенные команды:** Android не предоставляет сторонней утилите универсальный доступ к текущим JobScheduler/AlarmManager задачам и shell-командам других приложений. Название класса receiver или заявленный JobService не означают фактическую активность. UsageStats показывает только доступные системе события.

**Приватность:** сведения о пакетах, событиях и выбранных файлах обрабатываются локально. Сервер для получения этих данных не используется. Права QUERY_ALL_PACKAGES считать доступом к чувствительному инвентарю; на клиентском телефоне показывать назначение и согласие.

**Тесты перед распространением:** OnePlus Android 16, Android 10 и Android 13; минимум 90 программ; список системных и пользовательских, категории игр, стороннее приложение с разрешением overlay и приемником BOOT_COMPLETED, отсутствие Usage Access, отмена системного удаления, batch-очистка без фактического подтверждения, удачная/неудачная SAF копия, невозможность удаления защищённых данных. Полный статус отдельных операций в настройках стороннему APK недоступен.

**Подпись:** CI debug APK может использовать новый сертификат. При несовпадении с 0.5 сохранить пользовательские файлы и удалить предыдущую бету перед установкой 0.6.

## Версия 0.5: запрос применимых диагностических разрешений
- «Центр разрешений → Запросить все применимые разрешения для диагностики»: показывает предварительное описание доступа и запрашивает через Android только ещё не выданные разрешения. Системных окон может быть несколько; в каждом можно отказать.
- Запрашиваются только runtime-права для реально реализованных модулей: контакты, информация о SIM, микрофон, камера, геолокация, Bluetooth (Android 12+) и уведомления (Android 13+).
- После системных ответов показывает количество предоставленных новых разрешений. По-прежнему можно выдавать доступы по одному при использовании конкретного теста.
- Не предоставляет и не обходит Usage Access, root, Device Owner, Accessibility, SYSTEM_ALERT_WINDOW или доступ к защищённым данным.
- Массовая выдача чувствительных доступов нежелательна на клиентских устройствах: включать только после осознанного согласия владельца.
- Подпись debug CI может меняться при каждой сборке: перед установкой 0.5 при несовпадении подписи сохранить экспортированные файлы и удалить предыдущую тестовую версию.

## Возможности 0.4: центр разрешений и реальные технические проверки

- Вход: «Обзор», «Приложения», «Тесты» или «Данные» → «Центр разрешений».
- Подтверждения: каждое чувствительное разрешение запрашивается только при запуске конкретного теста, отдельным диалогом Android. Отказ не ломает остальные функции.
- READ_PHONE_STATE: состояние SIM, телефонные модули, оператор и тип сети. IMEI/IMSI не читаются.
- RECORD_AUDIO: 1,5 секунды проверка локального RMS-уровня микрофона без сохранения аудио.
- CAMERA: кратковременная попытка открыть и закрыть модуль камеры без записи изображения.
- ACCESS_COARSE_LOCATION + ACCESS_FINE_LOCATION: точность и возраст *последней* GPS-фиксации; без чтения/вывода координат.
- BLUETOOTH_CONNECT (Android 12+): состояние Bluetooth и количество ранее сопряжённых устройств; без поиска новых устройств.
- POST_NOTIFICATIONS (Android 13+): локальное тестовое уведомление.
- READ_CONTACTS: прежняя функция ручного экспорта VCF; выбор файлов через системный диалог без доступа ко всему накопителю.
- PACKAGE_USAGE_STATS — **специальный** доступ, не runtime-разрешение. История UsageEvents может блокироваться Restricted Settings на стороннем APK.
- В этом релизе **не запрашиваются** SMS, Accessibility, чтение всех чужих уведомлений, SYSTEM_ALERT_WINDOW, QUERY_ALL_PACKAGES, MANAGE_EXTERNAL_STORAGE, Device Admin, системные и root-права: для них нет реализованных обоснованных функций.
- Обычная установка APK не превращает программу в системное приложение и не даёт ADB/root. Ведение скрытого фонового журнала, удалённое управление и отправка данных не реализованы.
- Бета-подпись может отличаться от старой сборки — сохранить экспорт, удалить прежнюю бету, затем установить 0.5. Тестирование на OnePlus Android 16 обязательно.

## Возможности 0.3 — AppUsage-подобный журнал
- Открывается через «Обзор», «Приложения» или «Данные» в установленном APK.
- Использует Android `UsageStatsManager.queryEvents()` и требует отдельного системного разрешения «Доступ к статистике использования».
- История переходов приложения на экран и в фон; запуска и остановки foreground-служб, если Android их предоставляет.
- Периоды 1 час / 24 часа / 3 дня; фильтры, поиск по названию или имени пакета, сводка и локальный экспорт CSV.
- История не передаётся на сервер, разрешение владелец телефона может отозвать.
- Нельзя обнаружить все обычные скрытые процессы, JobScheduler, таймеры, сетевые запросы и запуски без доступных системных событий.
- Android хранит UsageEvents ограниченное время (обычно несколько дней), а прошивки могут ограничивать выдачу.
- Протестировать на OnePlus Android 16: выдать разрешение, запустить стороннее приложение, посмотреть историю и экспорт CSV.

## Интерфейс 0.2 (сохранён)
- Отдельная сервисная панель с разделами **Обзор / Приложения / Тесты / Данные**.
- Обзор: Android, модель, SoC (если доступно), ABI, CPU-потоки, разрешение окна, заряд/температура батареи, RAM и раздел /data, тип сети, число датчиков.
- Приложения с доступными ярлыками запуска: поиск по имени/package, сортировка, иконки, версия, дата установки, тип приложения и список **объявленных опасных разрешений** с текущим статусом.
- Действия с приложениями: открыть, перейти к системным настройкам, инициировать системное окно удаления с подтверждением владельца.
- Тесты: цветовые экраны, тач-панель с рисованием, короткий звук, вибрация, значения акселерометра/гироскопа/датчика света/приближения. Тест датчиков ограничен по времени; отслеживание останавливается при закрытии.
- Прежний экран 0.1 с резервной копией VCF, файлами, отчётами JSON и статистикой использования доступен через **Данные → Открыть инструменты и экспорт**.

## Разрешения
- `android.permission.VIBRATE` — обычное разрешение для короткой проверки вибромотора.
- `android.permission.ACCESS_NETWORK_STATE` — определение типа сети.
- `android.permission.READ_CONTACTS` — только по запросу владельца при экспорте VCF через старый экран.
- `android.permission.PACKAGE_USAGE_STATS` — разрешение Usage Access вручную для статистики, можно отозвать.
- Управление приложениями/удаление — только в системном UI Android, без скрытой установки и удаления.
- **Нет** QUERY_ALL_PACKAGES, широкого доступа ко всем файлам, root, Accessibility-сервиса, Device Owner, удалённого подключения или загрузки персональных данных на сервер.

## Установка
1. Установить APK на собственный тестовый Android 8+.
2. **Если уже установлена версия 0.1/0.2**, новая отладочная подпись CI может не совпадать. Сохраните экспортированные данные, удалите старую версию через настройки Android и установите 0.6 заново. Не пытайтесь обходить Android Signature Mismatch.
3. Нажмите «Открыть» или найдите Android Control Hub в списке приложений.
4. Разрешения на контакты и Usage Access включать только при необходимости.
5. Прежде чем распространять приложение среди клиентов, подготовьте подписанный release-APK с **постоянным защищённым ключом**, политику конфиденциальности и пользовательское тестирование.

## Проверки
- Проверено в CI: `assembleDebug` на Java 17 / AGP 8.7.3 / SDK 35.
- **Не проверено на физическом устройстве**: фактические касания, датчики, звук, вибрация, окна системной установки/удаления и разрешения прошивок.
- Тест-план: Android 8, 10, 13, 15, 16; фильтр и сортировка 90+ программ; меню сведений/удаления; сенсоры доступны и недоступны; многократное открытие/закрытие диалогов; отказ в разрешениях; экспорт VCF/JSON; запуск без интернета.
- Размеры RAM / раздела могут отличаться от системы из-за различий в методах учёта.

## Сборка
Открыть каталог `android-companion` в Android Studio. Gradle 8.9 / JDK 17 / compile SDK 35. Команда `gradle :app:assembleDebug`. В GitHub Actions workflow `.github/workflows/android-companion.yml` создаёт проверяемый debug artifact и один release-тег для бета-версии. Отладочный APK — **не финальный клиентский выпуск**.
